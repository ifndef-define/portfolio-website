Advanced Custom Keyboard Platform

Hall Effect Analog MUX Firmware Multi-MCU

What I Was Trying to Understand

Mechanical keyboards fascinated me, but I wanted to go deeper: what if I could sense key actuation analog-style? How do distributed systems work when you have multiple MCUs? How do you handle high-speed communication and power efficiency in a device that mostly sleeps? This project became an exploration of firmware architecture, analog sensing, and embedded systems at the consumer product level.

What I Built

A keyboard platform using Hall-effect magnetic switches with analog multiplexing (ADC), 128x64 SSD1306 TFT display on I2C, QSPI flash storage for profiles, USB HID host communication, and an RP2040 satellite MCU for matrix scanning. Firmware implements low-power modes, debouncing, and profile management.

Architecture:

  • Main MCU (RP2040): Managed HID communication, profile storage, and display control
  • Satellite MCU: Handled matrix scanning and analog key sensor reads
  • Hall-Effect Sensing: Analog multiplexing with ADC for pressure-sensitive input
  • Display (SSD1306): Real-time feedback on key state and active profile
  • QSPI Flash: Stored multiple keyboard profiles for different use cases
  • USB HID: Full USB host implementation for seamless OS integration

Key Takeaways

Analog sensing requires careful calibration and noise filtering. Scaling to multiple MCUs means thinking about synchronization and data consistency. Power-aware architecture (sleep states, clock gating) is essential for battery-powered devices.

Technical Insights:

  • Analog Calibration: Hall sensors drift with temperature; needed per-key calibration routine
  • IIR Filtering: Low-pass filtering essential for debouncing analog signals
  • Multi-MCU Sync: Serial protocol with checksums for reliable inter-MCU communication
  • Power Efficiency: RP2040 sleep mode consumed nearly nothing; biggest drain was display
  • USB HID Compliance: RP2040 USB stack made HID implementation straightforward

Lessons Learned

Building a complete product-like system revealed many hidden complexities: proper power sequencing, state machine correctness across MCUs, and the importance of debug interfaces. The project taught me that firmware quality requires thinking about edge cases and recovery paths.

Tech Stack

Main MCU: RP2040 (Dual Arm Cortex-M0+)
Satellite MCU: STM32L series (Low power ARM Cortex-M0+)
Sensors: Hall-Effect switches, ADC multiplexing
Display: SSD1306 128x64 OLED via I2C
Storage: QSPI Flash (profile management)
Communication: USB HID, Serial (inter-MCU), I2C
